DIAPOSITIVA 02 · ¿QUÉ ES FINE-TUNING?

De Conocimiento General a Especialización de Dominio

El fine-tuning (ajuste fino) es el proceso mediante el cual se toma un modelo de lenguaje previamente entrenado —una red neuronal de gran escala que ha aprendido patrones generales del lenguaje a partir de un conjunto masivo de datos— y se entrena nuevamente utilizando un conjunto de datos más pequeño y específico. En otras palabras, se trata de adaptar un modelo con conocimientos generales para que se especialice en un dominio o tarea concreta.

DIAPOSITIVAS 02 Y 03 · CICLO DE VIDA DEL LLM

Pretraining → Fine-Tuning → Inference & Deployment

1. Pretraining: Establece una base amplia de conocimiento a partir de datos web masivos (Web data → Base LLM).
2. Supervised Fine-Tuning: Conecta una base de conocimiento específica o privada (Specific Private Knowledge Base) y un dataset de tareas para optimizar el modelo.
3. Inference & Deployment: El Fine-tuned LLM genera respuestas expertas en aplicaciones del mundo real.

DIAPOSITIVA 04 · FINE-TUNING - ELEMENTOS

Los 4 Elementos Esenciales del Ajuste Fino

Todo proceso de Fine-Tuning exitoso articula estos cuatro componentes:

1 Modelo preentrenado (Base LLM)

Es capaz de responder preguntas generales, redactar textos creativos, resumir artículos o traducir idiomas gracias a su pre-entrenamiento masivo.

2 Objetivo del ajuste fino

Convertir este modelo generalista en un experto generador de respuestas de un área de conocimiento específica (ventas, soporte técnico, legal, salud, etc.).

3 Datos de ajuste fino (Task-specific dataset)

Conjunto de datos curado compuesto por interacciones reales (por ejemplo, conversaciones históricas verificadas entre usuarios y agentes humanos).

4 Modelo ajustado (Final Model)

Tras el proceso de fine-tuning, el modelo mejora significativamente su comprensión de las consultas específicas: ajusta su tono, agrega políticas internas e incorpora la jerga o terminología propia de la organización.

01 / POST-ENTRENAMIENTO Y REFINAMIENTO (SLIDES 5, 6 Y 7) · 5 MIN

SFT, RLHF, DPO y Matriz Fine-Tuning vs RAG

POST-TRAINING
DIAPOSITIVA 05 · PRE-TRAINING VS FINE-TUNING

Diferencias con el Pre-Entrenamiento

Las principales diferencias entre el pre-entrenamiento (pre-training) y el ajuste fino (fine-tuning) se encuentran en su escala, objetivo, tipo de datos y costo computacional. Ambos procesos cumplen funciones complementarias dentro del ciclo de desarrollo de un LLM:

• Pre-Training (from scratch): Datos masivos Unlabeled (Common Crawl, arXiv, Wikipedia) → Modelo Base como LLaMA (Meta).
• Fine-Tuning (Instructured / Supervised): Misma arquitectura con pesos actualizados usando datos Labeled (ej. 175 tareas semilla Self-Instruct) → Modelo instruido como Alpaca.

DIAPOSITIVA 06 · TIPOS DE POST-ENTRENAMIENTO

Las 4 Ramas del Post-Training of LLMs

✔ 1. Fine-tuning Supervisado (SFT): Supervised Fine-Tuning, Adaptive Fine-Tuning y Reinforcement Fine-Tuning.
✔ 2. Alineación (Alignment): RLHF (RL with Human Feedback), RLAIF (RL with AI Feedback) y DPO (Direct Preference Optimization).
✔ 3. Mejora del Razonamiento (Reasoning Enhancement): Self-Refine y RL for Reasoning.
✔ 4. Optimización de Eficiencia (Efficiency Optimization): Model Compression, Parameter-Efficient Fine-Tuning (PEFT / LoRA) y Knowledge Distillation.

DIAPOSITIVA 07 · TIPOS DE REFINAMIENTO

5 Estrategias de Refinamiento de Modelos

Selecciona la técnica adecuada según la cantidad de ejemplos y el nivel de adaptación requerido:

✔ 1. Transfer Learning

Aprendizaje por Transferencia: Reutiliza representaciones aprendidas en una tarea general para impulsar una nueva tarea específica.

✔ 2. Supervised Fine-tuning (SFT)

Ajuste Fino Supervisado: Re-entrena el modelo con pares entrada-salida etiquetados de alta calidad.

✔ 3. Few-shot Fine-tuning

Ajuste Fino con Pocos Ejemplos: Adapta el comportamiento cuando solo dispones de un conjunto reducido de muestras.

✔ 4. Instruction Fine-tuning

Ajuste Fino por Instrucciones: Enseña al modelo a seguir órdenes estructuradas, formatos JSON y directrices de usuario.

✔ 5. Domain-Specific Fine-tuning

Adaptación de Dominio: Especializa el vocabulario y criterio del LLM en medicina, leyes, finanzas o soporte técnico.

★ Regla de Oro en Clase

Fine-Tuning cambia la forma de actuar y el tono; RAG inyecta hechos y documentos actualizados.

02 / RETRIEVAL-AUGMENTED GENERATION (SLIDES 8 Y 9) · 5 MIN

Arquitectura RAG en 4 Etapas

RAG MODEL
DIAPOSITIVA 08 · DEFINICIÓN DE RAG

Combinación de Recuperación + Generación

La arquitectura Retrieval-Augmented Generation (RAG) destaca por su capacidad para combinar de manera estratégica dos enfoques que históricamente han evolucionado por separado: los métodos basados en recuperación de información (retrieval-based) y los modelos generativos (generation-based). La articulación de ambos permite generar respuestas con una mayor precisión, profundidad contextual y fundamentación documental.

DIAPOSITIVA 08 · BÚSQUEDA EN TIEMPO REAL

Conocimiento Actualizado sin Reentrenar Pesos

La arquitectura RAG introduce un mecanismo de búsqueda documental en tiempo real que complementa el conocimiento del modelo (consultando bases vectoriales como Pinecone o Qdrant, manuales de producto, APIs de configuración e historial), permitiéndole acceder a información actualizada y específica antes de generar una respuesta.

CREA · api/src/services/vector.service.js (Extracto de Búsqueda Semántica) 
1export function similitudCoseno(vecA, vecB) {
2  let dot = 0, normA = 0, normB = 0;
3  for (let i = 0; i < vecA.length; i++) {
4    dot += vecA[i] * vecB[i];
5    normA += vecA[i] * vecA[i];
6    normB += vecB[i] * vecB[i];
7  }
8  return Number((dot / (Math.sqrt(normA) * Math.sqrt(normB) || 1)).toFixed(4));
9}
10
11export const vectorService = {
12  listarDocumentos() { return DOCUMENTOS_SEMILLA; },
13  indexarDocumento(dto) {
14    const nuevo = { id: `doc-0${DOCUMENTOS_SEMILLA.length + 1}`, ...dto, vector: generarEmbedding(`${dto.titulo} ${dto.contenido}`) };
15    DOCUMENTOS_SEMILLA.unshift(nuevo);
16    return nuevo;
17  },
18  buscarSemantico(pregunta, topK = 4) {
19    const queryVector = generarEmbedding(pregunta);
20    const resultados = DOCUMENTOS_SEMILLA.map((doc) => ({ ...doc, vectorScore: similitudCoseno(queryVector, doc.vector) }))
21      .sort((a, b) => b.vectorScore - a.vectorScore)
22      .slice(0, topK + 1);
23    return { queryVector, resultados };
24  },
25};
03 / RAG - RERANKED (SLIDE 10) · 5 MIN

El Filtro Maestro: Rerankers y Corrective RAG

RERANKER

Dentro del flujo de trabajo de un sistema RAG, los rerankers cumplen una función estratégica que impacta directamente en la calidad de la información recuperada y, en consecuencia, en la calidad de las respuestas generadas por el LLM.

Retrieval→Reranker / Evaluator→Filter Noise→Generator
✔ 1. Mejoran la Precisión

Reevalúan semánticamente cada documento recuperado frente a la pregunta exacta para colocar en el top #1 la evidencia más pertinente.

✔ 2. Elevan la Calidad del LLM

Al alimentar el Prompt con fragmentos altamente relevantes y ordenados, el LLM genera respuestas fundamentadas y libres de alucinaciones.

✔ 3. Reducen Ruido y Redundancia

Mediante el flujo Retrieval Evaluator (Correct / Ambiguous / Incorrect) y Knowledge Refinement (Decompose → Filter → Recompose), eliminan fragmentos irrelevantes.

3export const rerankerService = {
4  ejecutarPipelineRAG(dto) {

6    let fragmentos = resultados.map((d) => ({ ...d, rerankScore: d.vectorScore }));
7    let ruidoEliminado = 0;
8    let evaluacionRecuperacion = "Ambiguous";
9
10    if (dto.useReranker) {
11      const reordenados = fragmentos
12        .map((doc) => ({ ...doc, rerankScore: calcularRerankScore(dto.pregunta, doc) }))
13        .sort((a, b) => b.rerankScore - a.rerankScore);
14      const filtrados = reordenados.filter((d) => d.categoria !== "ruido" && d.rerankScore >= 0.45);
15      ruidoEliminado = Math.max(1, reordenados.length - filtrados.length);
16      fragmentos = (filtrados.length ? filtrados : reordenados).slice(0, dto.topK);
17      evaluacionRecuperacion = fragmentos[0]?.rerankScore >= 0.7 ? "Correct" : "Ambiguous";
18    }
19    // Ensambla Paso 3 (Prompt) y Paso 4 (Post Processing & Response)
20    return { reranker: { activo: dto.useReranker, evaluacionRecuperacion, ruidoEliminado }, arquitectura4Pasos: { ... } };
21  },
22};
